## 1. Executive summary

**Expected result of a formal RGAA audit today: "non conforme" (well under 50 % of applicable criteria met).**

The application is built on solid foundations — MUI dialogs (focus trap, Escape, `aria-modal`),
FullCalendar 6 built-in keyboard support, MUI Autocomplete combobox pattern, `<html lang>` that
follows the UI language — but a handful of **global, theme-level defects** make almost every page
of any RGAA sample fail the same criteria:

1. **Keyboard focus is practically invisible everywhere** (RGAA 10.7). The twake-mui theme removes
   MUI's focus shadow and no outline is ever drawn; verified live: a focused button has
   `outline: none; box-shadow: none`, only the faint ripple pulse remains.
2. **The brand colours fail contrast** (RGAA 3.2, 3.3). Private app primary `#F67E35` with white text
   is **2.64:1** (needs 4.5:1) — every contained button, "Create", selected days. Public app primary
   `#0a84ff` is 3.36–3.65:1, `text.secondary` 3.49–3.64:1, `error.main` 3.61:1 (confirmed by axe).
3. **Page title never changes** (RGAA 8.6) — `Twake Calendar` on every view and every public page.
4. **No `<h1>`, broken heading hierarchy, no skip link, incomplete landmarks** (RGAA 9.1, 12.6, 12.7).
5. **Many form fields are labelled by their placeholder only, or not at all** (RGAA 11.1, 11.2)
   — ~25 fields in the private app, the booking form in the public app.
6. **Several core features are mouse-only** (RGAA 7.3): desktop date fields, calendar colour picker,
   events in the Schedule (list) view, calendar "more" menu at narrow width/zoom, mobile result lists.
7. **Legal prerequisites are entirely missing**: no accessibility statement, no "Accessibilité :
   non conforme" mention, no feedback contact, no multi-year plan (art. 47 loi 2005-102, décret 2019-768).

Because RGAA scoring is per criterion over the whole sample (a criterion fails if it fails on any
page), the six global fixes above (theme focus ring, palette, titles, headings/landmarks/skip link,
field labels, MUI locale) would flip the largest number of criteria for the smallest effort.

## 2. Method and limits

### 2.1 Source review
Four review passes, each with exhaustive grep (`aria-*`, `role=`, `tabIndex`, `onClick` on
`div`/`span`/`Box`, `outline`, `alt=`, `document.title`, `label`, `placeholder`, `Snackbar`…) and
reading of the relevant MUI / FullCalendar / twake-mui sources in `node_modules` to confirm runtime
behaviour:

- Application shell and theme (index.html, layout, menubar, sidebar, settings, palette, focus)
- Calendar views (FullCalendar grid, event chips, mini calendar, calendar list, colour picker, print)
- Forms, dialogs, popovers and search in the private app (event form, preview, attendees, calendar
  modal, access rights, search, booking-link configuration)
- Public application (booking flow, public event preview) and legal / tooling prerequisites

Contrast ratios were computed with the WCAG relative-luminance formula on the actual hex values,
alpha colours blended onto their real background.

### 2.2 Live scan (`mcp-accessibility-scanner`, axe-core 4.x, Chromium)
The production bundles were started with the e2e docker stack (`e2e/src/test/resources/docker-twake-calendar-e2e.yml`).

| Page | Result |
|---|---|
| `public/booking/<unknown id>` (booking page, error state) | 6 violations: unnamed language combobox (4.1.2), contrast `#828385`/`#f3f6f9` 3.49:1, `#ff3347` 3.61:1, `#0a84ff`/`#f3f6f9` 3.36:1 (1.4.3), no `main` landmark, no `h1`, content outside landmarks |
| `public/excal?jwt=<invalid>` (public event preview, error state) | 4 violations, same families |
| Keyboard, public layout | Focused `Help` button: `outline: none`, `box-shadow: none`, background transparent — only the MUI ripple pulse shows focus. Language combobox: no outline, no shadow |
| Reflow 320 px, public error page | No horizontal scroll |
| `localhost:8099` (private app, before login) | When the identity provider cannot be reached, the app shows the **"Calendar has been updated — Refresh"** fallback: misleading message for every user, `<html lang="en">`, decorative inline SVGs not hidden, no live region |

**Limits of the live scan.** The authenticated private application could not be scanned live: the
scanner's browser cannot reach the e2e identity provider (self-signed TLS certificate, and
bypassing it was out of bounds for this session). The populated booking flow and event preview
could not be scanned either (no data could be seeded). All findings on those screens come from the
source review; the ones whose runtime effect could not be fully established are tagged
**[runtime]**. A formal audit must be run on a reachable test instance with a logged-in account
(see remediation `R-01`).

### 2.3 Not covered
- Screen reader rendering (NVDA + Firefox, JAWS + Chrome, VoiceOver iOS, TalkBack — the RGAA test
  environment) — to be done during the formal audit.
- Downloadable documents (ICS export, printed PDF) beyond the print HTML structure.
- E-mails sent by the backend (invitations), and third-party apps linked from the app grid.

## 4. Positive points

- `<html lang>` follows the UI language at runtime (`common/src/hooks/useDocumentLanguage.ts`); print document sets `lang`.
- Viewport does not block zoom; mobile layout below 900 px gives a usable 320 px reflow (public error page verified live).
- All dialogs are MUI `Dialog`s: `role="dialog"`, `aria-modal`, focus trap, Escape, focus restore; `ResponsiveDialog` wires `aria-labelledby` with `useId`.
- FullCalendar 6 accessibility active: events in month / week / day views focusable and operable with Enter/Space, "+N" link with `aria-expanded`, column headers with full-date labels.
- Gesture alternatives exist: navigation buttons for swipe, "Create" button / FAB for grid selection.
- `PeopleSearch` follows the MUI Autocomplete combobox pattern with a hidden `<label>`; chip removal by keyboard.
- Menubar icon buttons all have translated names; MUI SVG icons are `aria-hidden` by default.
- `FreeBusyIndicator` exposes its status as text; `WeekDaySelector` / `MonthSelector` use real buttons with `aria-pressed`; `ToggleButton`s expose `aria-pressed`.
- `ClickableField`, `SectionPreviewRow`, `DesktopResultItem`, `BookingLinkOverlay` implement keyboard-operable `role="button"` correctly.
- Error and websocket snackbars are persistent with an explicit OK button; snackbars use `role="alert"`.
- French locale is complete (0 missing keys); calendar checkboxes are real labelled checkboxes; a contrast helper (`getAccessiblePair`) already exists.
- Event status uses shape in addition to colour (strikethrough, dashed border, icons) — a good basis for text alternatives.
- An e2e accessibility suite already exists and locates elements by accessible name — a ready-made place for automated checks.
