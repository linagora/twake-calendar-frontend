## 1. Verdict

**Still "non conforme" (< 50 %) in a formal RGAA audit**, but for far fewer reasons, almost all of
them waiting for a design decision rather than for code.

- **Fixed:** 10 of the 17 blockers. Every keyboard dead end found in the pre-audit now has a
  keyboard path: date and time fields, colour picker, Schedule view events, calendar actions at
  high zoom, booking-link rows, mobile result and option lists. Screen readers now get names for
  previously unnamed buttons, dialogs, form fields and groups, and are told about status changes.
- **Still failing on every page:** a handful of RGAA criteria, each because its fix is visible
  and therefore blocked:
  - focus indicator — 10.7, R-03;
  - colour contrast — 3.2 and 3.3, R-08;
  - skip link — 12.7;
  - visible labels and required markers — 11.1, 11.2 and 11.10, partly;
  - message duration — 13.1, R-09, not in this batch.

  Since RGAA scores each criterion over the whole sample, these alone keep the rate under 50 %.
- **Quickest path to "partiellement conforme":** design validation of the blocked list
  (section 5). After that come R-03, R-08 and R-09, then the remaining major findings (R-18 to
  R-22).

## 4. New findings (axe-core, e2e scans)

| ID | Page | Rule | Finding |
|---|---|---|---|
| NEW-01 | Calendar | `listitem` | Sidebar list items rendered outside any list |
| NEW-02 | Calendar | `scrollable-region-focusable` | FullCalendar's scrolling grid cannot be scrolled from the keyboard |
| NEW-03 | Settings | `list` | The settings navigation list contains buttons instead of list items |

The e2e scans list these three rules as known failures for their pages, together with CAL-11,
CAL-16 and `color-contrast`, so that any *other* regression fails the build. Each entry must be
removed from the test when its fix lands.

## 5. What blocks partial compliance: the visible changes to validate

Ranked by the number of RGAA criteria each one unlocks on the whole sample:

1. **Focus indicator** (R-03) → 10.7, 3.3 on every page.
2. **Accessible palette** (R-08) → 3.2, 3.3 on every page (the only rule the live scans still
   report on the public pages).
3. **Skip link** visible on focus → 12.7.
4. **Visible labels and required markers** in place of placeholders (event form, booking form,
   searches) → 11.1, 11.2, 11.10.
5. **In-app accessibility mention** "Accessibilité : non conforme" linking to the statement →
   legal obligation.
6. **Translated MUI / date picker texts** (displayed strings) → 8.7.
7. Then, not visible but not in this batch: R-09 (messages ≥ 6 s, errors persistent), R-18 (event
   accessible names), R-21 (focus management), R-22 (attendee popover).

The detailed list of blocked items is in each entry of the action plan, under
**Blocked (visible change)**.
