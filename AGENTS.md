# Agents

- `CHANGELOG.md` is managed by twake-changelog, the changelog automation of the Twake software factory: it reviews the commits merged since its last pass and opens a pull request writing them into `[Unreleased]`, and a section per version released since. Do not edit `CHANGELOG.md` in a change: give your commit a subject a user can read (conventional commits: `feat:`, `fix:`, `feat!:` for a breaking change), name its issue or pull request, and put what an operator must do when upgrading under `BREAKING CHANGE:` or an `Upgrade` section of the commit message. To fix a wording, edit it in the pull request of twake-changelog.
- Releasing: first bring the changelog up to date with every commit merged so far: run twake-changelog on this repository (Changelog proposals, in Other automations of the software factory dashboard) and merge the pull request it opens, or check it found nothing to propose; then, on an up-to-date `main`, bump the version and rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD` with a new empty `## [Unreleased]` above it (a version tagged without this step gets its section from twake-changelog at its next pass). Create the GitHub release of the tag with that section as notes; if the tag came first, once the pull request of twake-changelog writing its section is merged.
